# MofuType 十二支·오행·MBTI 성격 및 관계 분석 설계

작성일: 2026-08-15
상태: 사용자 최종 승인 완료, 구현 계획 작성

## 1. 결정 요약

MofuType의 기존 동물점 유사 체계를 폐기하고 일본 사용자에게 익숙한
十二支, 일본 四柱推命 방식의 오행·음양, MBTI를 결합한 독자적인 성격 및
관계 분석 서비스로 다시 설계한다.

제품의 세 핵심 레이어는 동등하게 관계 분석에 참여한다.

1. 양력 출생연도의 十二支 캐릭터
2. 출생일과 선택적 출생시각으로 계산한 四柱·오행·음양
3. 선택적으로 입력한 MBTI 네 축

외부 점술 API와 유료 API는 사용하지 않는다. 계산은 무료 오픈소스 역법
라이브러리를 격리한 순수 로컬 모듈에서 실행한다. 원본 생년월일과
출생시각은 서버, 저장소, URL, 로그 또는 분석 이벤트에 남기지 않는다.

사용자에게 궁합 점수, 백분율, 순위, 좋은 궁합 또는 나쁜 궁합을 표시하지
않는다. 관계를 이해하고 대화하는 데 도움이 되는 정성 카테고리와 근거를
제공한다.

## 2. 용어와 제품 경계

### 2.1 十二支와 干支

제품의 캐릭터 12종은 엄밀히 `十二支`다. 한국어 대화에서 흔히 말하는
`12간지`를 뜻하지만, 60개 조합인 十干十二支 전체를 캐릭터 체계로 만들지는
않는다.

사주 계산 내부에서는 十干과 十二支로 이루어진 四柱를 사용한다. 화면의
대표 十二支 캐릭터와 내부 四柱의 연주는 서로 다른 경계 규칙을 가진다.

### 2.2 폐기하는 체계

다음 타입, 그룹, 공식, 이미지와 표현을 모두 폐기한다.

- fawn
- raccoon
- black-panther
- wolf
- koala
- cheetah
- lion
- elephant
- pegasus
- 기존 tiger, sheep, monkey 이미지
- MOON, EARTH, SUN 그룹
- 기존 `AnimalId`, `AnimalGroup`, `animalVersion`
- 일주·월주 인덱스로 자체 동물을 배정하는 공식
- 일본어 UI의 `動物占い`, `動物タイプ` 표현

호랑이, 양, 원숭이는 十二支에도 존재하지만 기존 이미지를 재사용하지 않고
새 12종 세트로 다시 제작한다.

### 2.3 엔터테인먼트 원칙

- 과학적 진단이나 절대적인 운명처럼 표현하지 않는다.
- 건강, 재정, 법률, 임신, 수명 등을 예측하지 않는다.
- 상생을 우월함으로, 상극을 나쁨이나 관계 단절 사유로 표현하지 않는다.
- MBTI 미입력 또는 출생시각 미입력을 무료 기능 제한으로 사용하지 않는다.
- 공식 캐릭터 체계, 공식 문구 또는 제삼자 점술 브랜드를 모방하지 않는다.

결과 하단에는 다음 고지를 표시한다.

> この分析は自己理解とコミュニケーションを楽しむためのもので、科学的・医学的な判定ではありません。

## 3. 입력과 시간 기준

### 3.1 입력 필드

- 그룹 닉네임: 공백 정리 후 1~20자
- MBTI: 16개 타입 또는 `모름`
- 생년월일: 네이티브 `input[type=date]`, 필수
- 출생시각: 네이티브 `input[type=time]`, 선택
- 출생시각 모름: 별도 체크박스
- 위치: 입력하지 않음

입력 범위는 1900-01-01부터 계산 당일까지다. 존재하지 않는 날짜, 미래
날짜, `HH:mm`이 아닌 시간, 16개 외 MBTI를 안정된 검증 오류로 거부한다.
`시간을 모름`을 선택하면 이미 입력한 시간값을 즉시 제거한다.

### 3.2 일본 사용자용 두 경계

화면에 표시하는 대표 十二支는 일본의 일반적인 연도 띠 인식에 맞춰 양력
1월 1일 00:00에 바뀐다.

四柱 계산은 일본 四柱推命에서 일반적으로 사용하는 절입 기준을 따른다.

- 연주: 해당 연도의 실제 立春 순간
- 월주: 실제 二十四節気의 절입 순간
- 일주: 일본 민간시 00:00 경계
- 시주: 입력한 일본 표준시 시각
- 시간대: `Asia/Tokyo` 고정
- 위치 및 진태양시 보정: 사용하지 않음

따라서 1월 또는 立春 전 출생자는 화면의 十二支 캐릭터와 四柱의 연지가
다를 수 있다. 이는 오류가 아니며 UI에서는 복잡한 원국 대신 짧은 도움말로
설명한다.

### 3.3 출생시각을 모르는 경우

- 시주는 생성하지 않는다.
- 연주·월주·일주, 十二支, MBTI 분석은 정상 제공한다.
- 정오나 임의 시각을 채우지 않는다.
- `出生時刻を使わない分析です`라고 표시하되 열등한 결과로 표현하지 않는다.

절입일 당일이면서 출생시각을 모르면 절입 전과 후 두 후보를 계산한다.

- 두 후보에 공통인 일간 오행·음양만 확정 사실로 사용한다.
- 전체 오행·음양 분포는 어느 후보도 임의 선택하지 않고 `null`로 둔다.
- 관계 엔진은 확정된 두 사람의 일간 관계만 사용하고 분포 기반 보완 문구는
  생략한다.
- 十二支와 MBTI 레이어는 정상 사용한다.
- 상세 화면에 절입 전후로 일부 오행이 달라질 수 있음을 알린다.

## 4. 로컬 계산 아키텍처

### 4.1 계산 경계

무료 오픈소스 역법 라이브러리는 어댑터 한 파일 안에 격리한다. 도메인
모듈과 UI는 라이브러리 타입을 직접 참조하지 않는다.

```text
사용자 입력
  → 엄격한 로컬 검증
  → 역법 어댑터로 四柱 사실 계산
  → 十二支·오행·음양·MBTI 파생 프로필 생성
  → 원본 생년월일과 출생시각 폐기
  → 파생 프로필만 Supabase RPC에 전달
```

외부 사주 API 호출, 위치 API 호출 및 원격 폴백은 없다. 라이브러리 로드나
계산이 실패하면 생년월일 기반의 다른 임의 타입을 만들지 않고 안전한 일본어
오류와 재시도를 제공한다.

### 4.2 결정성

동일 입력은 브라우저, 테스트 및 배포 환경에서 항상 같은 결과를 반환해야
한다.

- 난수와 현재 시각을 파생 공식에 사용하지 않는다.
- 시스템 시간대와 브라우저 언어에 따라 계산을 바꾸지 않는다.
- 정렬 순서나 A/B 입력 방향에 따라 대표 관계를 바꾸지 않는다.
- 역법 및 문구 규칙은 명시적인 엔진 버전으로 고정한다.

## 6. 파생 프로필과 개인정보

### 6.1 저장 모델

```ts
type FiveElement = "WOOD" | "FIRE" | "EARTH" | "METAL" | "WATER";
type Polarity = "YIN" | "YANG";

interface DerivedProfile {
  version: 1;
  zodiacId: ZodiacId;
  mbti: MbtiType | null;
  dayMaster: {
    element: FiveElement;
    polarity: Polarity;
  };
  fiveElements: Readonly<Record<FiveElement, number>> | null;
  yinYang: Readonly<Record<Polarity, number>> | null;
  calculationMode: "date-time" | "date-only";
  boundaryState: "exact" | "solar-term-ambiguous";
  engineVersion: "mofu-eto-four-pillars-v1";
}
```

시간을 입력하면 오행 및 음양 합계는 8글자 기준이고, 모르면 6글자 기준이다.
비교 시 원시 개수만 비교하지 않고 전체 글자 수에 맞는 정성 범주로
정규화한다. 시간 미입력을 결핍이나 낮은 정확도 점수로 취급하지 않는다.

절입 전후 후보의 프로필이 다른 경우 DB에는 공통으로 확정 가능한 일간과
`solar-term-ambiguous` 상태만 저장한다. `fiveElements`와 `yinYang`은 null이며
원국 후보 자체는 저장하지 않는다.

### 6.2 저장하지 않는 값

- 생년월일
- 출생시각
- 전체 四柱 원국 문자열
- 천간·지지 원문 배열
- 절입 전후 후보 원국
- 원본 입력의 해시

위 값은 Supabase, localStorage, sessionStorage, URL, 로그, 오류 추적 및 분석
이벤트에 기록하지 않는다. 관계 분석에 필요한 최소 파생값만 저장한다.

## 7. 관계 분석 엔진

### 7.1 공개 관계 카테고리

```ts
type RelationshipCategory =
  | "NATURAL_INTERLOCK"
  | "EXPANDING_POSSIBILITIES"
  | "POSITIVE_STIMULATION"
  | "LEARNING_EACH_OTHERS_PACE";
```

일본어 표시는 다음과 같다.

- `自然にかみ合う関係`
- `一緒に可能性を広げる関係`
- `違いがよい刺激になる関係`
- `お互いのペースを学ぶ関係`

네 카테고리는 순위가 아니며 좋음/나쁨의 척도가 아니다.

### 7.2 十二支 레이어

六合은 자연스럽게 맞물림으로 분류한다.

- ねずみ–うし
- とら–いのしし
- うさぎ–いぬ
- たつ–とり
- へび–さる
- うま–ひつじ

三合 그룹 안의 모든 서로 다른 두 타입은 가능성 확장으로 분류한다.

- さる・ねずみ・たつ
- いのしし・うさぎ・ひつじ
- とら・うま・いぬ
- へび・とり・うし

六冲은 좋은 자극으로 분류한다.

- ねずみ–うま
- うし–ひつじ
- とら–さる
- うさぎ–とり
- たつ–いぬ
- へび–いのしし

같은 타입 및 그 외 조합은 서로의 속도를 배우는 관계로 분류하고 해당
조합에 맞는 중립적 문구를 제공한다. 판정은 A/B 순서와 무관하다.

### 7.3 오행·음양 레이어

일간 관계와, 확정되어 있을 때 두 사람의 전체 오행 분포를 함께 사용한다.

- 상대의 두드러진 오행이 나의 부족한 오행을 보완하면 자연스럽게 맞물림
- 木生火, 火生土, 土生金, 金生水, 水生木의 흐름이면 가능성 확장
- 木克土, 土克水, 水克火, 火克金, 金克木의 흐름이면 좋은 자극
- 같은 오행과 같은 음양이 강하게 겹치거나 위 규칙이 없으면 속도 학습

상생과 상극의 방향은 A용 및 B용 상세 문구에만 반영한다. 대표 관계
카테고리와 pair key는 대칭이어야 한다. `solar-term-ambiguous` 프로필은
확정된 일간의 동일·상생·상극 관계로 카테고리를 만들되, null인 분포를
추정하거나 오행 보완 문구를 생성하지 않는다.

### 7.4 MBTI 레이어

16×16 점수표를 사용하지 않고 E/I, S/N, T/F, J/P 네 축을 각각 설명한다.

1. 네 축이 같으면 자연스럽게 맞물림
2. 세 축이 같으면 가능성 확장
3. 정확히 두 축이 같고 서로 다른 두 축이 E/I와 J/P이면 속도 학습
4. 정확히 두 축이 같고 그 외 조합이면 좋은 자극
5. 같은 축이 0~1개면 속도 학습

위 순서는 서로 배타적이므로 추가 우선순위나 점수표가 필요 없다. MBTI가
한쪽이라도 null이면 이 레이어 전체를 생략한다.

### 7.5 균형형 최종 판정

각 레이어는 카테고리 하나 또는 제외 상태를 반환한다. 숫자 점수나 가중치를
계산하지 않고 카테고리 다수결을 사용한다.

1. 같은 카테고리가 두 개 이상이면 이를 대표 카테고리로 선택한다.
2. 세 레이어가 모두 다르면 十二支 카테고리를 선택한다.
3. MBTI 미입력으로 두 레이어만 남고 둘이 다르면 十二支를 선택한다.
4. 十二支는 생년월일 필수 입력으로 항상 존재하므로 대표 관계도 항상
   결정된다.

공개 제목과 대표 카테고리는 대칭이다. `forPersonA`, `forPersonB` 조언과
오행의 방향 문구만 사람별로 다를 수 있다.

```ts
interface RelationshipResult {
  category: RelationshipCategory;
  headline: string;
  zodiacInsight: ZodiacInsight;
  fiveElementInsight: FiveElementInsight;
  mbtiInsight: MbtiInsight | null;
  tips: {
    together: string;
    forPersonA: string;
    forPersonB: string;
  };
}
```

결과 모델에는 score, percentage, rank 및 이에 준하는 숫자 궁합 필드를 두지
않는다.

## 8. Supabase 스키마와 초기화

### 8.1 새 멤버 모델

`group_members`의 기존 `animal_id`, `animal_group` 및 구 프로필 JSON을
제거하고 다음 정보를 둔다.

- `zodiac_id`
- `mbti`
- `derived_profile`
- `profile_version`

DB CHECK와 SECURITY DEFINER RPC 양쪽에서 다음을 검증한다.

- 정확한 12개 ZodiacId
- MBTI 16개 또는 null
- 정확한 JSON 키와 스칼라 컬럼 일치
- exact 상태일 때 오행 5키 및 음양 2키의 0 이상의 정수
- exact `date-time` 합계 8, exact `date-only` 합계 6
- solar-term-ambiguous 상태일 때 두 분포가 모두 null
- `calculationMode`, 경계 상태 및 분포 nullability의 일관성
- 허용된 엔진 버전
- birth, date, time, dob 및 변형 원본 키 거부

클라이언트의 직접 INSERT/UPDATE/DELETE는 계속 금지하고 인증된 RPC만 쓰기를
수행한다. 그룹 최대 30명, 멤버 전용 조회, 토큰 해시, pair canonicalization,
Realtime 및 그룹 전체 관계 해제의 기존 보안 경계는 유지한다.

### 8.2 기존 데이터 폐기

기존 데이터를 변환하거나 이중 읽기하지 않는다.

- 모든 기존 그룹, 멤버 및 관계 해제 행 삭제
- 기존 `animal_group` enum과 동물 제약 제거
- 기존 초대 링크 만료
- 브라우저의 구버전 그룹 토큰 및 폼 draft 무효화
- 구버전 프로필을 발견하면 새 입력 화면으로 이동

마이그레이션 이력 자체는 보존한다. 새 파괴적 마이그레이션에서 레거시 데이터를
명시적으로 비운 뒤 스키마를 교체한다. 실제 원격 적용 직전에는 Supabase
project ref가 MofuType 대상인지 읽기 전용으로 확인하고 삭제 대상과 복구 불가
범위를 사용자에게 다시 알린다.

## 11. 오류와 복구

- 입력 오류: 필드 가까이에 구체적인 일본어 안내
- 역법 모듈 로드 실패: 원본 입력을 로그하지 않고 재시도 제공
- Supabase 구성 오류: 입력 폼을 반복 제출하지 않고 구성 안내와 재시도 제공
- 그룹 정원 30명: 프로필 입력 전에 safe preview로 안내
- 만료된 초대: 생년월일 입력 전에 차단
- Realtime 끊김: 마지막 안전 스냅샷 유지, 직렬화된 재동기화와 수동 새로고침
- 이미지 실패: 十二支 일본어 이름 텍스트 fallback

## 13. 현재 코드 영향 범위

현재 저장소에서 레거시 동물 모델은 다음 영역에 걸쳐 있어 단순 rename으로
처리하지 않는다.

- `src/lib/astrology`: AnimalId, AnimalGroup, 카탈로그와 로컬 파생기
- `src/lib/relationship`: 그룹 우세 matrix와 관계 문구
- `src/lib/supabase`: 모델, repository, 생성 타입
- `supabase/migrations` 및 pgTAP: enum, 컬럼, JSON CHECK, RPC 인자와 fixture
- `src/features/group-graph`: 노드 데이터, topology snapshot과 avatar
- 온보딩 create/join 폼 및 테스트
- Playwright seed와 30명 그래프 fixture
- 기존 설계 및 구현 문서
- `public/animals` 에셋과 production source safety 검사

구현은 별도 worktree에서 테스트 우선으로 진행하며 현재 다른 컨텍스트가
수정 중인 UI와 새 에셋을 덮어쓰지 않는다.
