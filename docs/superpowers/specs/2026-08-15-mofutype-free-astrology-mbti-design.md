## 1. 목적

MofuType의 현재 임시 로컬 계산기를 무료 오픈소스 역법 엔진 기반의 브라우저 계산으로 고도화한다. 계산 결과는 공식 `動物占い®`의 60 캐릭터 체계나 문구를 복제하지 않고, 사주 역법에서 얻은 사실과 MofuType 자체 규칙을 조합한 12동물 엔터테인먼트 분석으로 제공한다.

핵심 목표는 다음과 같다.

- 외부 유료 사주 API를 사용하지 않는다.
- 생년월일과 출생시간을 외부 서버로 전송하거나 DB에 저장하지 않는다.
- 일본 사용자만 대상으로 하며 위치 입력을 받지 않는다.
- 현재 12동물, 3그룹, 그룹 관계 그래프와 이전 프로필을 유지한다.
- MBTI를 모르는 사용자도 불이익 없이 완전한 동물·오행 관계 결과를 받는다.
- 관계 결과에 점수, 백분율, 최악의 궁합 같은 단정적 표현을 사용하지 않는다.

## 2. 제품 경계와 표현 원칙

### 2.1 독자 서비스 경계

MofuType은 공식 동물점 서비스가 아니다. 공식 캐릭터 분류표, 60캐릭터 명칭, 공식 해설 문구, 상표 표현을 사용하지 않는다. 기존 MofuType의 12동물 에셋과 명칭은 유지하되 배정 공식, 성향 문구, 관계 문구는 모두 독자적으로 작성한다.

모든 결과 화면에는 다음 안내를 표시한다.

> 四柱推命の暦情報とMBTIをもとにした、MofuType独自のエンターテインメント分析です。

출생시간을 입력하지 않은 결과에는 다음 안내를 추가한다.

> 出生時間を使わない簡易分析です。時間を推測して補完していません。

### 2.2 해석 한계

- 건강, 재정, 법률, 임신, 수명 등의 예측을 하지 않는다.
- 과학적 진단이나 절대적 운명처럼 표현하지 않는다.
- 관계에 우열을 매기거나 관계 중단을 유도하지 않는다.
- 숫자 기반 내부 계산값은 사용자에게 궁합 점수로 노출하지 않는다.

## 3. 입력 규칙

입력은 기존 온보딩 폼을 유지한다.

- MBTI: 16개 유형 중 하나 또는 `모름`
- 생년월일: 네이티브 `input[type=date]`, 필수
- 출생시간: 네이티브 `input[type=time]`, 선택
- 출생시간 모름: 별도 체크
- 위치: 입력하지 않음

일본 전용 서비스이므로 모든 날짜와 시간은 `Asia/Tokyo` 기준으로 해석한다. 위치나 진태양시 보정은 하지 않는다. 역법 계산에서 기준 경도가 필요하면 일본 표준시 기준 자오선인 동경 135도를 내부 고정값으로 사용한다.

날짜 경계는 예측 가능성을 위해 일본 민간시의 00:00으로 고정한다. 23:00부터 다음 날 일주로 보는 일부 학파 규칙은 적용하지 않는다. 다만 23:00~00:59가 자시에 해당하는 시간지지 계산은 날짜 경계와 별도로 처리한다. 이 선택은 MofuType 계산 버전에 포함해 고정한다.

출생시간을 모르면 정오 등 임의의 시간을 채우지 않으며 시주와 시간대 해석을 완전히 생략한다.

## 4. 계산 아키텍처

### 4.1 엔진 선택

주 계산 엔진은 MIT 라이선스, TypeScript, 무의존성인 `lunar-typescript`를 사용한다. 라이브러리는 초기 페이지 번들에 넣지 않고 생년월일 입력이 시작될 때 동적 import로 미리 불러온다.

외부 사주 API 호출은 없다. 계산은 브라우저 안에서 끝난다.

```text
입력 시작
  → 계산 모듈 백그라운드 로드
  → 제출 및 입력 검증
  → 일본 표준시 기준 사주 사실 계산
  → MofuType 12동물 파생
  → MBTI를 포함한 프로필 생성
  → 원본 입력 폐기
  → 파생 프로필만 Supabase 저장
```

### 4.2 엔진 인터페이스

구현은 라이브러리를 도메인 로직에서 격리한다.

```ts
interface AstrologyEngine {
  calculate(input: AstrologyInput): Promise<AstrologyFacts>;
}

interface AstrologyFacts {
  dayPillarIndex: number; // 0..59
  monthPillarIndex: number; // 0..59, 절기 기준
  dayStem: HeavenlyStem;
  dayBranch: EarthlyBranch;
  primaryElement: FiveElement;
  polarity: "YIN" | "YANG";
  elementBalance: Readonly<Record<FiveElement, number>>;
  hourKnown: boolean;
}
```

`LunarTypescriptAstrologyEngine`만 라이브러리 타입을 알고, 나머지 코드는 위의 내부 타입만 사용한다. 오행 분포는 사용 가능한 연주·월주·일주와, 시간이 알려진 경우 시주의 천간 및 지지 주 오행을 세어 만든다. 숫자는 내부 파생 사실일 뿐 궁합 점수로 표시하지 않는다.

### 4.3 실패와 폴백

라이브러리 로드 또는 계산이 실패해도 온보딩을 막지 않는다. 현재의 결정론적 `localAstrologyProvider`를 버전 고정 폴백으로 사용하고 `DerivedProfileV1`을 생성한다.

- 현재 화면에는 `簡易分析` 배지를 표시한다.
- 저장된 v1 프로필도 상세 오행 데이터가 없는 간이 분석으로 취급한다.
- 오류 메시지에는 라이브러리명, 스택, 생년월일, 출생시간을 포함하지 않는다.
- 잘못된 날짜·시간·MBTI는 폴백하지 않고 기존의 안정된 검증 오류로 반환한다.

## 5. 독자 12동물 배정 규칙

공식 동물점의 60캐릭터 대응표를 사용하지 않는다. MofuType의 배정 버전 `mofu-animal-v1`은 다음과 같다.

```text
coreIndex   = 절기 기준 60갑자 일주 인덱스
seasonIndex = 절기 기준 60갑자 월주 인덱스
animalIndex = positiveModulo(coreIndex + seasonIndex, 12)
animalId    = ANIMAL_ORDER[animalIndex]
```

`ANIMAL_ORDER`는 현재 저장소의 순서를 그대로 고정한다.

1. fawn
2. raccoon
3. black-panther
4. sheep
5. wolf
6. monkey
7. tiger
8. koala
9. cheetah
10. lion
11. elephant
12. pegasus

동물 그룹은 현재 카탈로그의 `MOON`, `EARTH`, `SUN` 매핑을 유지한다. 동물의 기본 성향 위에 일간의 주 오행과 음양을 문구 레이어로 더한다. 출생시간이 알려진 경우에만 시주 기반의 숨은 반응 레이어를 추가한다.

이 공식은 버전 없이 변경하지 않는다. 변경이 필요하면 새 배정 버전을 만들며 기존 사용자의 동물을 재계산하지 않는다.

## 6. 프로필 데이터와 개인정보 경계

### 6.1 브라우저에만 존재하는 데이터

다음 값은 계산 중 메모리에만 존재하고 계산 후 폐기한다.

- 생년월일
- 출생시간
- 전체 사주 원국
- 일주·월주 인덱스와 천간·지지 원본

로컬 저장소, 세션 저장소, URL, 로그, 분석 이벤트, Supabase에 위 값을 쓰지 않는다. 동일 입력 캐시가 필요하면 원본 문자열을 영속화하지 않는 메모리 수명 캐시만 사용한다.

### 6.2 저장 프로필 버전

기존 데이터는 `DerivedProfileV1`로 유지한다.

```ts
interface DerivedProfileV1 {
  version: 1;
  animalId: AnimalId;
  animalGroup: AnimalGroup;
  mbti: MBTIType | null;
  calculationMode: "date-time" | "date-only";
}
```

신규 주 엔진 성공 결과는 `DerivedProfileV2`로 저장한다.

```ts
type FiveElement = "WOOD" | "FIRE" | "EARTH" | "METAL" | "WATER";

interface DerivedProfileV2 {
  version: 2;
  animalId: AnimalId;
  animalGroup: AnimalGroup;
  mbti: MBTIType | null;
  calculationMode: "date-time" | "date-only";
  primaryElement: FiveElement;
  polarity: "YIN" | "YANG";
  elementBalance: Readonly<Record<FiveElement, number>>;
  hourKnown: boolean;
  engineVersion: "mofu-four-pillars-v1";
  animalVersion: "mofu-animal-v1";
}

type DerivedProfile = DerivedProfileV1 | DerivedProfileV2;
```

`hourKnown`과 `calculationMode`는 서로 일치해야 한다. DB는 v1의 기존 정확한 5키 구조와 v2의 정확한 키 구조를 각각 허용하고, 동물-그룹 매핑, MBTI, 오행 키, 정수 분포, 버전 문자열을 서버에서도 검증한다. RPC와 직접 테이블 제약은 같은 규칙을 적용한다.

기존 scalar 컬럼 `animal_id`, `animal_group`, `mbti`는 유지하고 JSON 프로필과 일치시킨다. 원본 출생정보로 추정 가능한 불필요한 간지 값은 저장하지 않는다.

## 7. 관계 알고리즘

관계 엔진은 대칭적인 정성 결과를 생성한다. A-B와 B-A는 동일한 pair key, 카테고리, 공개 제목과 해제 상세를 가진다. 사용자에게 점수나 백분율을 반환하는 필드는 만들지 않는다.

### 7.1 레이어 순서

1. 기존 동물 그룹 관계를 기본 분위기로 결정한다.
2. 두 프로필이 모두 v2이면 오행 관계를 더한다.
3. 양쪽 MBTI가 모두 있으면 네 축 상호작용을 더한다.
4. 두 프로필이 모두 v2이면 음양에 따른 표현 강도를 더한다.
5. 양쪽 모두 출생시간을 입력한 v2일 때만 숨은 반응 문구를 더한다.

v1-v1 또는 v1-v2 조합은 공통으로 존재하는 정보만 사용한다. 누락 정보를 중립값으로 꾸며내지 않는다.

### 7.2 오행 관계

오행은 다음 정성 관계 중 하나로 분류한다.

- 동일 오행: 익숙함과 공통 리듬
- 상생 방향: 한쪽이 다른 쪽을 북돋는 흐름
- 상극 방향: 관점과 행동 방식의 긴장

상생·상극의 방향은 상세 문구에만 반영하며 사람의 우열로 표현하지 않는다. `elementBalance`는 과다·부족 경향의 보조 문구에 사용하되 숫자나 퍼센트를 표시하지 않는다.

### 7.3 MBTI 관계

16×16 점수표를 만들지 않는다. 네 축마다 세 패턴을 정의해 총 12개의 독립 규칙으로 관리한다.

- E/E, I/I, E/I
- S/S, N/N, S/N
- T/T, F/F, T/F
- J/J, P/P, J/P

이 규칙은 대화 시작 방식, 정보 해석, 판단 표현, 생활 리듬의 차이를 설명한다. MBTI가 한쪽이라도 없으면 MBTI 레이어 전체를 생략하며 동물·오행 결과의 품질이나 공개 범위를 낮추지 않는다.

### 7.4 공개 카테고리

관계의 대표 카테고리는 다음 네 가지다.

- `自然に噛み合う`
- `違いが刺激になる`
- `言葉の翻訳が必要`
- `ペース調整が鍵`

카테고리는 좋음/나쁨 순서가 아니며 어떤 카테고리에도 공포 또는 단절 유도 문구를 사용하지 않는다.

## 8. 무료와 300엔 공개 범위

### 8.1 무료

- 본인의 동물 타입과 한 줄 설명
- 주 오행과 음양 성향(v2만)
- 출생시간 기반 보조 성향(시간을 입력한 v2만)
- 관계 대표 카테고리
- 동물·오행 조합의 짧은 관계 설명
- 그룹 그래프의 전체 노드와 관계선
- 해제 여부 표시

### 8.2 그룹 단위 300엔 해제

결제 해제는 현재 설계대로 그룹 전체에 귀속한다. 그룹이 한 번 해제되면 결제 당시 구성원뿐 아니라 이후 들어온 구성원의 새 관계도 상세 열람 대상이다.

각 두 사람 관계에서 다음을 공개한다.

- 끌리는 지점
- 충돌하기 쉬운 지점
- 겉으로 말하지 않는 반응
- 잘 통하는 대화 방식
- 다툰 뒤 회복 방식
- 장기적으로 맞춰야 할 습관
- 양쪽 MBTI가 있을 때 네 축별 관계 해설

이 문서는 관계 해제 도메인 규칙만 다룬다. 실제 결제사업자 선정, PayPay 연결, 결제 웹훅 구현은 별도 설계 범위다.

## 9. 성능 설계

- 초기 랜딩 번들에 역법 라이브러리를 포함하지 않는다.
- 사용자가 생년월일 입력을 시작할 때 동적 import를 시작한다.
- 제출 후 결과 표시 목표는 대표 모바일 환경에서 1초 이내다.
- 준비된 엔진의 계산이 메인 스레드를 50ms 넘게 점유하면 Web Worker로 이동한다.
- 중복 제출은 같은 메모리 수명 동안만 계산 결과를 재사용한다.
- 로딩 중에는 중복 제출을 막고 접근 가능한 진행 상태를 알린다.
- 라이브러리 청크 로드 실패는 폴백 처리하며 무한 재시도하지 않는다.

## 10. 오류 처리

- 사용자 입력 오류는 기존 안정 코드 `INVALID_BIRTH_DATE`, `INVALID_BIRTH_TIME`, `INVALID_MBTI`를 유지한다.
- 엔진 내부 오류는 안전한 일본어 일반 메시지와 함께 폴백한다.
- DB가 v2를 거절하면 원본 입력을 재전송하지 않으며, 임의로 v1으로 다운그레이드해 저장하지 않는다.
- 프로필 파싱 실패는 해당 멤버를 잘못 추정하지 않고 기존의 안전한 그룹 오류 상태로 보낸다.
- 관계 문구 생성은 지원되지 않는 버전이나 enum을 만나면 명시적으로 실패하며 기본 점수를 만들지 않는다.

## 11. 검증 전략

### 11.1 역법 및 동물 엔진

- 공개적으로 교차 확인 가능한 날짜의 일주·월주 골든 픽스처
- 윤년과 월말, 절기 직전·직후
- 일본 시간 22:59, 23:00, 23:59, 00:00 경계
- 출생시간 있음/모름의 시주 포함 여부
- 동일 입력의 결정성
- 12동물 인덱스 및 음수 modulo 안전성
- 넓은 날짜 표본에서 모든 동물이 도달 가능하고 심각한 분포 붕괴가 없는지
- 라이브러리 실패 시 v1 폴백과 `簡易分析` 표시

### 11.2 프로필 및 개인정보

- v1/v2 판별형 파싱과 상호 호환
- v2 정확한 키, enum, 정수 오행 분포, 동물-그룹 일치
- RPC와 직접 DB 쓰기 모두 잘못된 v2 거부
- 원본 생년월일·시간 키 및 값이 저장 payload, local/session storage, URL, 로그에 없음
- 서버 번들 및 Supabase 함수에 역법 계산 입력이 전달되지 않음

### 11.3 관계 엔진

- 모든 오행 동일·상생·상극 방향
- MBTI 네 축의 12패턴
- MBTI null일 때 불이익과 빈 문구 없음
- v1-v1, v1-v2, v2-v2 조합
- A-B/B-A 대칭성과 canonical pair key
- 네 공개 카테고리와 모든 상세 섹션
- 결과 객체와 화면 소스에 score, percentage, `%`, `％` 없음
- 30명 그룹의 435개 관계 생성 및 기존 그래프 메모화 유지

### 11.4 성능 및 통합

- 초기 페이지에서 역법 청크가 로드되지 않음
- 입력 시작 시 preload, 제출 시 단일 import
- 대표 모바일 브라우저 계산 시간 측정
- 50ms 기준 초과 시 Worker 경로 검증
- 기존 v1 그룹의 생성·초대·실시간 그래프·해제 흐름 회귀 테스트

## 13. 승인된 결정 요약

- 계산은 무료이며 브라우저 안에서 수행한다.
- `lunar-typescript`를 지연 로드하고 현재 로컬 엔진을 폴백으로 유지한다.
- 일본 전용, 위치 입력 없음, `Asia/Tokyo` 및 135E 고정 기준을 사용한다.
- 출생시간 모름을 허용하고 시주를 추측하지 않는다.
- MofuType 독자 12동물 공식과 버전 고정 문구를 사용한다.
- 사주 원본은 저장하지 않고 최소한의 파생 프로필만 v2로 저장한다.
- 기존 v1 프로필과 그룹을 깨뜨리지 않는다.
- MBTI는 네 축 12규칙이며 모름에 불이익이 없다.
- 관계는 정성 카테고리만 사용하고 점수·백분율을 금지한다.
- 무료 결과와 그룹 단위 300엔 상세 해제를 유지한다.
